Claude 代理检查 2026.10.07.2

两种模式（在 Clash Verge 托盘菜单开关「虚拟网卡模式」切换）
  Claude 模式：虚拟网卡开。CLI、VS Code、专用浏览器、桌面端都走固定出口。
  国内模式：虚拟网卡关，国内 App（如三角洲行动、飞书）正常使用；
    CLI、VS Code、专用浏览器照常走固定出口，桌面端和普通浏览器不受保护。
  两种模式下 Clash 都要保持「规则」模式并保持运行；退出 Clash 后 Claude 不可用（不会改走直连）。
  系统代理建议一直开着：它不影响 Claude；三角洲行动、飞书等出问题是虚拟网卡造成的。

日常只需要两件事
  1. 用之前：看状态图标；需要细节时双击桌面「代理网络检查」，或在终端运行 claude-proxy。
     结论下面显示当前模式，并按入口列出 CLI / VS Code / 网页版 / 桌面端 能不能用。
     不能用时，每个「原因」下面有一行「处理」，照做即可；终端里还可以按 R 选修复方案。
  2. 用的过程中：后台「使用中守护」约每 30 秒核对一次出口。
     出口 IP 不符：自动断开 Claude 的固定出口连接，并弹窗提醒。
     Clash 被切到全局或直连：弹窗提醒（关闭虚拟网卡切到国内模式不会弹窗）。
     守护本身由开机启动项运行；它退出后会在 30 秒内被自动拉起。

各入口怎么受保护
  CLI / VS Code：走专用端口 127.0.0.1:17892，只能从固定出口出去；
    Clash 切到全局或直连也不影响这个端口。端口不可用时请求直接失败，不会改走别的线路。
  网页版：只用桌面「Claude 专用浏览器」（或「Claude 打开授权链接」）。
    每次打开前自动检查固定出口和 WebRTC 防护，不通过就不打开，并弹窗说明。
    普通浏览器打开 claude.ai 不在保护范围。
  桌面端：不走专用端口，只在 Claude 模式下靠 Clash 规则进入固定出口，未做专项验证；建议用上面三种。

什么情况会判为不能用
  - Clash / Mihomo 没运行，或专用端口不可用
  - 两处独立公网检测没有都返回预期的固定 IP
  - 使用中守护没运行、没有按时更新，或已因出口不符阻断 Claude
  - Claude 或 VS Code 设置被改动（只影响对应入口；只是 VS Code 设置有问题时，CLI 仍可用）
  - 网页版另需 WebRTC 防护确认（见下文）
  Clash 模式只影响桌面端：国内模式、全局或直连模式下桌面端判为不受保护，其余入口不受影响。

常见处理
  守护没运行：claude-proxy → R →「启动使用中守护」。
  守护已阻断：先联系线路供应商确认出口恢复，再 claude-proxy → R →「恢复本机代理配置」。
    修复会先通过只供检查用的端口 17893 核对出口，正确才放开 Claude；不符时继续阻断。
  出口 IP 变了：这是供应商侧的变化，本机修不了；恢复前不要使用 Claude。
  Clash 被切到全局或直连：在 Clash Verge 切回「规则」模式。
  Clash 没运行：打开 Clash Verge；仍不通过时 claude-proxy → R →「恢复本机代理配置」。
  关闭 Clash 窗口不等于停止内核；界面关了但内核还在运行时，代理仍可能正常。

命令
  claude-proxy            使用前检查，通常几秒；不需要先打开 Claude，不会自动修复。
                          终端里结束后可选：R 修复方案、D 详细证据、C 重新检查、Q 结束。
                          修复方案先显示改动、影响和恢复方式，只有输入 YES 才执行。
  claude-proxy -Full      另启临时未登录 Chrome，提前检查网页版（约 1 分钟）。
                          桌面「代理网络检查」用的就是它，并保存报告到
                          %USERPROFILE%\.codex\ClaudeNetwork\reports\desktop-last-check.json。
  claude-proxy -Details   显示逐项证据，不改变判定标准。
  claude-proxy -Repair    直接执行「恢复本机代理配置」并重新检查；可能重启或重载 Clash。
  其他参数：-Runtime（打开 Claude 后核验实际请求）、-LaunchCheck（启动入口内部使用）、
            -Workspace（指定项目目录）、-Json / -Output / -NoPrompt（脚本使用）。

修复方案
  恢复本机代理配置：调用原恢复后端，恢复受管理的代理组、规则和 Claude / VS Code 设置，
    可能启动或重载 Clash；原后端用 DPAPI 保存改动前文件。不能修复供应商、账号或物理网络问题。
  启动使用中守护：在后台启动已有的守护（单实例），不修改文件。
  设置 Chrome WebRTC 保护：备份后只写当前用户的一个 Chrome 策略值，影响该用户全部 Chrome 资料
    和音视频通话；执行结果给出单值回滚命令。网页版检查已有其他通过方式，一般不需要它。

网页版的 WebRTC 防护
  临时浏览器实测：Chrome 实际生效的设置必须是 disable_non_proxied_udp，没有按网址的例外；
  独立 STUN 正对照能收到响应；浏览器原生 ICE 完成，没有异常公网候选，也没有发出 STUN UDP。
  设置来源接受两种：Chrome 强制策略；或命令行设置生效，且专用浏览器资料里没有能改写
  WebRTC 设置的扩展（持有 privacy 权限或存有 WebRTC 偏好）。
  专用资料登录了 Google 账号时，普通 Chrome 的扩展会随同步装进来，策略也可能强制安装扩展，
  所以每次打开专用浏览器都会重新核查；出现这类扩展时会点名并阻止打开。
  专用浏览器还禁用了 QUIC 和投屏发现（避免局域网 Cast TCP 8009 绕过代理），只作用于专用浏览器。

结果和退出码
  ENVIRONMENT_READY / 0  使用前检查通过（以按入口列出的结果为准）
  LAUNCH_READY / 0       CLI 启动入口的条件满足
  PROXY_READY / 0        网络预检通过，供专用浏览器入口使用
  CLAUDE_OBSERVED / 0    仅 -Runtime：运行中的 Claude 实例都已关联真实请求
  NOT_READY / 2          存在明确问题
  INCOMPLETE / 3         证据不足，不把未知当成通过

边界
  不输出或另存密码 / token，不读 Cookie，不登录或调用模型；配置凭据只在内存里比较。
  守护约每 30 秒核对一次，出口变化后最多约 30 秒才会阻断。
  Clash 被切到全局或直连时只弹窗提醒，不阻断；CLI、VS Code 和专用浏览器不受模式影响。
  国内模式下桌面端和普通浏览器里的 Claude 不受保护。
  不保证账号权益、地区资格、免封禁或供应商永久静态 IP。
  任意工具、MCP、WSL、SSH 和普通浏览器不属于全流量统一出口保证。
